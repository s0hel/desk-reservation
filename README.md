# Deskflow — flex workspace booking

Mobile-first desk and room booking for employers running flex-seating offices.

- [`docs/PRD.md`](docs/PRD.md) — what we're building and why
- [`docs/TECHNICAL_DESIGN.md`](docs/TECHNICAL_DESIGN.md) — how. Section references in code comments (`TDD §6.4`) point here.

**Status: Phase 0 complete** (see TDD §21). The schema, tenant isolation, the booking
correctness mechanism, auth, and an Expo app that signs in and lists seeded resources
all exist and are verified. Booking itself is Phase 1.

## Layout

```
apps/mobile/        Expo app (SDK 57, expo-router, TypeScript)
services/api/       FastAPI + PostgreSQL
packages/shared/    Policy reason codes, mirrored into Python
packages/api-client/ TypeScript client generated from the OpenAPI schema
docs/               PRD and technical design
```

## Getting started

Requires Docker, [uv](https://docs.astral.sh/uv/), Node 22 and pnpm 11.

```bash
cp .env.example .env
pnpm install
make up          # postgres, redis, mailpit
make migrate
make seed        # Example Corp: Berlin HQ, 2 floors, 120 desks, 6 rooms
make api         # http://localhost:8000  (docs at /docs)
```

Then the app:

```bash
cd apps/mobile && npx expo start
```

Sign in with `priya.raman@example.com` — any seeded address works.

### Running on a real device

`apps/mobile/.env` defaults to `http://localhost:8000`, which on a phone means *the phone*.
Set `EXPO_PUBLIC_API_BASE_URL` to your machine's LAN address.

This app needs a **development build**, not Expo Go (TDD §8.1) — Expo Go cannot load the
custom native configuration the camera, push and geofence work in Phase 2 will require.
`ios/` and `android/` are generated by `expo prebuild` and are gitignored:

```bash
cd apps/mobile
npx expo run:ios      # requires full Xcode, not just Command Line Tools
npx expo run:android
```

## Things that are load-bearing

**Double-booking is prevented by the database, not by application code.** `bookings` carries
a GiST exclusion constraint over `(resource_id, time_range)`, partial on active statuses
(TDD §6.4). There is no locking anywhere in the booking path. `tests/test_booking_concurrency.py`
fires eight simultaneous bookings at one desk and asserts exactly one wins; it runs on every PR.

**Tenant isolation is structural.** Every table has `FORCE ROW LEVEL SECURITY` keyed on
`current_setting('app.org_id')`, and the API's database role has no `BYPASSRLS`. A session
with no tenant context returns *nothing*, not everything. One dependency in
`app/api/deps.py` issues the `SET LOCAL`, and there is no code path that opens a session
without it. `tests/test_tenant_isolation.py` includes a check that every table has RLS
forced, so a new table added without it fails CI.

The single deliberate exception is `org_domains`, which needs a SELECT-only global policy
because email→tenant routing happens before a tenant is known (FR-1.3). It exposes only
`domain → organization_id`.

**A day is defined by the site's timezone**, never the device's or the server's
(TDD §5). `app/core/time.py` is the only module allowed to convert, and its tests cover
real 23- and 25-hour DST days.

**There is no calendar integration**, in either direction (PRD §5.3, TDD §7). Rooms are
ordinary resources booked only in this app. The one thing that follows: rooms must be made
unbookable in the customer's directory, or they will be double-booked from Outlook and we
cannot detect it.

## Development-only sign-in

`POST /v1/auth/dev-login` exists so Phase 0 is usable before any customer IdP is configured.
It is gated twice: by `ENABLE_DEV_LOGIN` plus `ENVIRONMENT=development`, and by a startup
assertion that refuses to boot if it is enabled outside development. It is excluded from the
OpenAPI schema, and a test asserts that. The real flow is OIDC with the API as relying party
(TDD §12.1).
